Unknown weekday: the Python raises ValueError lazily, only when a candidate matches day and month; ported as ArgumentException with the same laziness
Weekday check does not change the resolved date, because the fallback loop finds the same day/month; it only decides whether the exception is raised
UCI start times: the legacy code keeps actual_start_at as text; the port reads a time of day (HH:mm or H:mm), drops any other value and records a parse_time error, so the rest of the film is kept
UCI language and screen names that are not text are stored as missing, and an empty name is stored as missing too (the legacy output step drops empty values); the legacy connector keeps any value
UCI slug that is not text: the legacy code builds the film address with the Python text form of the value; the port skips the film and records a parse_programming_movie error
UCI requests are not retried: the legacy retry_request makes 3 attempts with waits of 2 s and 4 s and never retries a 403; the port makes one attempt per day (NFR-04 needs a package that is not approved yet)
UCI headers: the connector only sends Accept: application/json; the User-Agent belongs to the HttpClient of the Scraper (the legacy code sent a browser User-Agent, which NFR-07 does not allow)
UCI showings are returned by the connector as the legacy connector builds them, one per format and variant, and are merged when they are stored (see the note on merged showings); the legacy output step (models.py) also unescapes titles and descriptions and unwraps /_next/image posters, and the port does not do this yet, neither in the connectors nor in persistence
UCI descriptions: WebUtility.HtmlDecode differs from Python html.unescape for names without a semicolon (&copy 2026), HTML5-only names (&check;), numeric references from 0x80 to 0x9F (&#150; is a dash in Python and a control character here) and invalid numeric references; TitleNormalizer has the same difference for titles
UCI quirks kept on purpose: a film whose performances are all on other days still gets an empty list of times for the day unless not_today is true; text between < and > in a description is removed even when it is not a tag; a data value that is an object or a string gives one parse_programming_movie error per key or character; a film with a blank title is kept with an empty normalized title
UCI cinema address: the catalog has Viale Centova, 1/D, 06132 Perugia (address confirmed by the maintainer; postal code and position taken from the legacy web map, mappa.js) and not Via Corcianese 200, Corciano from the legacy backend configuration (CINEMA_LOCATIONS); the two legacy sources disagree, and the coordinates have not been checked against a map service
The Space browser fallback is not ported: when any request failed, the legacy code switched to CloakBrowser, a browser built to pass bot protections (NFR-07 forbids that). The port stops at the first failed or refused request, drops what it had read, as the legacy API path did, and records one error with phase scrape (legacy: scrape_fallback), the cinema page as URL and the failed request in the detail
The Space requests: one attempt each (the legacy retry_request makes 3 attempts with waits of 2 s and 4 s, and does not retry a 403), a pause of 1 s before each day (legacy: none), and only Accept: application/json from the connector (the legacy code also sent a browser User-Agent and the cinema page as Referer). The guest session is made of cookies kept by the HttpClient; nothing is read from the body of the first answer
The Space dates and times: the port reads the forms of datetime.fromisoformat with a calendar date (ISO week dates, which Python also accepts, are not read). As in the legacy code an offset is checked and not applied, so a group dated 2026-06-11T22:00:00Z stays on 11 June. A start time that is not a date and time is cut to five characters as in the legacy code: 9:05 is stored as 09:05, and a text that still is not a time of day is dropped with a parse_time error
The Space values that are not text: a synopsis, a screen or an attribute name of another type is stored as missing (the legacy connector keeps it), and a filmId that is not text or a number skips the film with a parse_api_film error
The Space showings are one per session in the connector, as the legacy connector builds them, and films without showings are kept; they are merged when they are stored (see the note on merged showings). The duration is the exception to the connector output: the port applies the legacy output normalizer in the connector, because the Domain stores minutes
The Space Corciano address: the catalog has Via Trasimeno Ovest 164 from the legacy backend configuration (CINEMA_LOCATIONS); the legacy web map (mappa.js) has Via Pierluigi Nervi 6 with another position. Which one is right has not been confirmed
Merged showings: the legacy output step _consolidate_showings is ported as ShowingConsolidator in the Domain and applied by the SQLite store to each film of a cinema, so scraped films that share a film row are merged too. As in the legacy code, one row is kept for each day, language, screen and set of attributes (compared as a text joined by commas), so showings in different screens stay apart. The legacy fuzzy merge of films across cinemas is not ported: cinemas share a film only when the title keys are equal
TMDB failures: the legacy fetch_backdrop stored "not found" for ever whenever a request failed (a wrong token, a rate limit and a server error included). The port stores only an answer: a failed lookup is tried again by the next run. A refused request (401, 403, 429) ends the lookups of the run, and so do three failures in a row (the legacy code went on). When the list of images cannot be had, the image of the search result is used, as in the legacy code. An answer that cannot be read fails the lookup (the legacy function raised and main.py logged it)
TMDB cache: the legacy code kept a file, keyed by the lowercased title, with no expiry. The port stores the result and its date on the film row (column BackdropFetchedAtUtc) and deletes it after 150 days, because the API terms forbid caching for more than 6 months
TMDB backdrops are looked up after all the cinemas, for the films with showings and no backdrop. As in the legacy code a backdrop sent by a cinema (Clarici sends one) is kept, and the title is searched without a year (the year parameter of fetch_backdrop is never used by main.py and is not ported)
TMDB attribution: the footer has the official logo and the notice of the API terms of 2023-10-20; the legacy page had an older wording and no logo
